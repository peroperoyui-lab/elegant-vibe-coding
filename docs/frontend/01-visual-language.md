# 前端设计语言：把“好看一点”翻译成可执行的设计

[返回目录](../../README.md) · [快速开始](../../QUICKSTART.md)

> 适用：网页、桌面 WebView、管理工具、资料管理工具。以下风格判断和默认数值是本手册的设计建议；规范性要求在[交互与无障碍](03-interaction-accessibility.md)单独标明。本章使用独立编写的界面示例。

一个有用的设计请求，应当同时交代**使用任务、视觉方向、结构规则、交互状态和验收方式**。“高级、简洁、现代”可以提供情绪，却很难决定正文该有多宽、哪个按钮值得强调、错误发生后页面保留什么。专业术语的价值，在于让这些决定变得明确。

**可以先记住这句：**“这是供用户长时间阅读和核对证据的工作站；采用克制的工具型界面，正文优先，低饱和背景与单一强调色；用排版、分组和边界建立层级，并完整呈现加载、空白、错误、选中与键盘焦点。”

## 1. 先选艺术方向，再谈组件样式

艺术方向（art direction）是一个产品如何呈现性格的总体决定。它包含字体、色彩、构图、图像、动效和文案语气。下面是常见的风格词汇，并非相互排斥的技术标准。

| 风格方向 | 视觉语言 | 适合的任务 | 用于工作站时的取舍 | 可直接使用的指令 |
| --- | --- | --- | --- | --- |
| 编辑式 / Editorial | 强排版、明确段落关系、克制装饰、有节奏的留白 | 阅读、知识库、报告、文献综述 | 文章区可有表达力，工具栏保持紧凑 | “让内容区具有编辑式排版：标题、导语、正文、注释层级清楚；工具区保持高效。” |
| 瑞士式 / Swiss / International Typographic Style | 规则网格、非对称构图、无衬线字、清楚的对齐线 | 档案、研究门户、目录 | 善用网格，留出中文长标题的弹性 | “以严格对齐、清晰字号层级和非对称网格建立秩序。” |
| 工具型 / Utilitarian | 紧凑信息、稳定布局、少量装饰、明确反馈 | IDE、资料管理工具、运营后台 | 让密度可调，同时保留阅读模式 | “采用工具型界面，优先可扫描、可操作、可恢复，装饰服务于分组。” |
| 人文极简 / Humanist minimalism | 温和中性色、自然文字节奏、柔和边界 | 笔记、写作、个人知识管理 | 避免把所有信息降成同一种灰度 | “使用温暖中性底色与清晰深色正文，保留少量绿色强调。” |
| 企业设计系统 / Enterprise | 稳定组件、统一语义、完整状态、可扩展规则 | 多模块生产工具 | 可以借鉴成熟组件规则，再建立自身比例与品牌 | “按企业工具的完整状态和组件一致性实现，同时保留自己的字体、间距和色彩。” |
| 新粗野 / Neubrutalism | 强边框、鲜明色块、夸张反差、可见构造感 | 个性品牌、创意工具、活动页面 | 长时间科研阅读可只借用局部强调 | “把新粗野风格用于专题入口和强调卡片，阅读工作区保持安静。” |
| 玻璃质感 / Glassmorphism | 半透明层、背景模糊、透光与悬浮感 | 层叠面板、短时展示、辅助浮层 | 正文底板需有稳定的实际对比度，低性能设备要有降级 | “只在轻量浮层应用透明材质，正文与数据区采用实色背景。” |
| 拟物 / Skeuomorphism | 借用真实物体的材质、形态或操作隐喻 | 有明确物理参照的工具 | 隐喻要帮助操作，材质纹理保持克制 | “保留便签的分组隐喻，主要阅读和编辑仍使用平面文字界面。” |
| 轻拟态 / Neumorphism | 近色表面、内外阴影、柔和凸起 | 少量展示性控件 | 单靠阴影难以表达边界，需额外的文字与状态线索 | “使用轻微表面起伏，并为按钮补充明确标签、边界与焦点状态。” |

**适用于文档管理界面的教学方向：工具型骨架 + 编辑式内容区 + 温和中性色。**资料处理任务需要反复切换材料、查看执行结果、阅读较长文本。可以让导航和列表稳定紧凑，让中心阅读区更舒展；右侧属性栏承载上下文信息。该方向是为任务推导出的教学建议。实际项目已经有品牌和设计系统时，先遵循现行基线；视觉实验在明确范围内验证。

### 如何借鉴一个参考界面

把参考图拆成可复用的原则：它的导航层级、文字比重、强调色分配、表格密度、面板比例和反馈方式。再给出你的场景差异。例如：“借鉴其双栏阅读和细分隔线，但把营销大标题改成项目标题；增加证据来源、任务状态和错误恢复入口。”

这样得到的是可迁移的设计判断。复制整套品牌图形、独特插画或页面文案，需要另外考虑授权。

## 2. 信息架构与布局词典

每个词都包含“看见什么”和“如何要求”。真正写提示词时，一次选择最相关的三到五个词即可。

| # | 中文 · English | 通俗解释与适用处 | 可复制指令 |
| --- | --- | --- | --- |
| 1 | 信息架构 · Information architecture | 内容和功能如何分类、命名与互相抵达；先于颜色 | “先梳理项目、材料、任务和成果的导航关系，再画页面。” |
| 2 | 应用框架 · App shell | 每页共用的导航、顶部区、内容容器 | “稳定 app shell，页面切换只替换工作区内容。” |
| 3 | 视觉层级 · Visual hierarchy | 用户第一眼、第二眼、第三眼分别注意到什么 | “第一层是当前任务，第二层是主要操作，元数据降到第三层。” |
| 4 | 内容层级 · Content hierarchy | 信息本身的主次关系，决定标题与语义结构 | “按项目—材料—段落建立内容层级，并使用对应标题级别。” |
| 5 | 视觉权重 · Visual weight | 面积、颜色、字重、位置造成的吸引力 | “降低边栏视觉权重，让正文成为主要视觉重心。” |
| 6 | 网格系统 · Grid system | 让不同区域共享对齐规则 | “统一标题、列表和工具栏的左边界，采用可伸缩的列网格。” |
| 7 | 栏间距 · Gutter | 两列之间的空间 | “把阅读区与属性栏之间的 gutter 设为明确的间距档位。” |
| 8 | 外边距 · Margin | 元素与外部邻居的距离 | “增加章节间 margin，保持同一章节内部紧凑。” |
| 9 | 内边距 · Padding | 容器边缘与内部内容的距离 | “统一面板 padding，标题与正文共享内侧对齐线。” |
| 10 | 留白 / 负空间 · Whitespace / Negative space | 为阅读、分组和强调提供空间，颜色未必是白色 | “扩大段落组之间的留白，使关系通过距离显现。” |
| 11 | 邻近分组 · Proximity grouping | 距离近的内容被理解为一组 | “字段标签贴近输入框，字段组之间用更大间距分隔。” |
| 12 | 对齐线 · Alignment axis | 多个元素共享的视觉起点 | “把图标、标题、正文的起点整理成两条稳定对齐线。” |
| 13 | 光学对齐 · Optical alignment | 按人眼感受修正几何上相等但视觉上偏移的内容 | “检查播放图标与按钮文字的光学居中，允许小幅视觉校正。” |
| 14 | 基线对齐 · Baseline alignment | 让不同字号的文字落在共同基线上 | “标题旁计数与标题基线对齐，避免垂直中心造成漂浮感。” |
| 15 | 视觉节奏 · Visual rhythm | 重复与变化形成稳定的阅读顺序 | “让章节间距保持节奏，重点区域通过一次明确的比例变化突出。” |
| 16 | 信息密度 · Information density | 同一空间承载多少有效信息 | “列表提供舒适和紧凑两档密度，保持字体与点击目标清晰。” |
| 17 | 渐进披露 · Progressive disclosure | 先展示完成当前任务需要的内容，再展开细节 | “默认展示结果与关键来源，参数与日志放进可展开详情。” |
| 18 | 主从视图 · Master–detail | 左侧选对象，右侧读详情 | “材料列表采用主从视图，切换材料保留列表滚动位置。” |
| 19 | 分栏视图 · Split view | 并列比较两份内容或工作面 | “支持原文与分析结果分栏阅读，分隔条可调整并有键盘替代。” |
| 20 | 上下文检查器 · Inspector | 展示当前选中对象的属性与操作 | “右侧 inspector 随选中材料更新，显示来源、版本和可用操作。” |
| 21 | 命令面板 · Command palette | 用搜索快速找到命令 | “增加命令面板，按名称查找项目操作，显示快捷键与可用状态。” |
| 22 | 面包屑 · Breadcrumb | 展示当前位置的路径 | “在深层材料详情中提供项目到文件夹的面包屑。” |
| 23 | 断点 · Breakpoint | 布局需要改变策略的宽度条件 | “按内容开始拥挤的位置设断点，并说明每个断点的布局行为。” |
| 24 | 容器查询 · Container query | 组件根据所在容器尺寸调整，适合可拖动面板 | “材料卡片随面板宽度切换布局，优先评估容器查询。” |

容器查询关注组件容器；媒体查询常用于视口或设备条件。对于桌面工作站，窗口很宽而某个侧栏很窄的情况尤其值得区分。具体浏览器和 WebView 支持以项目目标环境核对。[MDN：Container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)

| 40 | 排版层级 · Typographic hierarchy | 用字号、字重、行距、位置表达信息层次 | “标题靠字号和位置区分，辅助信息靠颜色和间距降级。” |

### 中文界面特别值得交代的细节

中文按钮往往短而信息密度高，英文标签可能突然变长。让按钮按内容适应，并保留合理最小尺寸；用真实名称、较长术语、混合标点、英文缩写和文件路径检查。段落中的粗体与颜色强调控制在有意义的位置。标题中的数字、括号和英文字母，需要和中文基线一同观察。

“每行 60–80 个字符”这类拉丁排版经验，直接移到中文时容易造成过宽的阅读区。CSS 的 `ch` 以字体中数字 `0` 的前进宽度为参照，也不代表一个汉字。[MDN：CSS length](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)手册建议从实际中文段落出发，比对每行约 30–45 个汉字时的视觉效果，再依屏幕与字体调整；这是设计起点，不是通用阈值。

| # | 中文 · English | 通俗解释与适用处 | 可复制指令 |

| 41 | 色相 · Hue | 颜色属于红、绿、蓝等哪一类 | “用偏绿的强调色表达品牌，错误状态继续保留明确语义。” |

设计变量让“次要文字”“危险操作”等意图可复用，并支持主题调整。组件在不同主题下可以继续使用相同的角色名称。[Atlassian：Design tokens](https://atlassian.design/tokens/design-tokens/)

| 63 | 缓动 · Easing | 动作加速、减速的方式 | “使用一致的缓动规则，让浮层进入与退出有明确节奏。” |
| 64 | 骨架屏 · Skeleton | 内容出现前占住相似结构 | “已知列表结构用骨架占位，保持最终标题和行高的位置。” |
| 65 | 空状态 · Empty state | 目前无内容时解释原因并引导下一步 | “区分首次使用、搜索无结果、筛选为空三种空状态。” |
| 66 | 乐观更新 · Optimistic update | 先反映可回退操作，再等待服务确认 | “仅对可恢复的小操作考虑乐观更新，失败时恢复状态并解释。” |
| 67 | 焦点环 · Focus ring | 让键盘用户知道当前操作对象 | “保留清晰 focus-visible 样式，并检查弹层遮挡。” |
| 68 | 选中态 · Selected state | 代表对象已被选为当前目标 | “选中材料有稳定标记，鼠标移走后仍可识别。” |
| 69 | 悬停态 · Hover state | 鼠标停留的临时状态 | “hover 提供轻反馈，主要信息在普通状态也能获取。” |
| 70 | 按下态 · Pressed state | 激活过程中或切换按钮开启后的状态，语义依组件而定 | “区分瞬时按下与切换按钮开启，并使用正确的状态属性。” |
| 71 | 减少动态效果 · Reduced motion | 尊重用户系统的动效偏好 | “检测 prefers-reduced-motion，减少位移、缩放和持续闪动。” |
| 72 | 感知性能 · Perceived performance | 用户感到系统是否及时、稳定、有回应 | “让点击反馈立即可见，长任务显示真实阶段，结果出现时保持布局稳定。” |

可供性（affordance）指对象提供的动作可能性；示意线索（signifier）帮助用户察觉可以怎样操作。例如可按的按钮提供触发动作的可能性，形状、文字和按下反馈则表达这种可能性。写需求时明确说“可执行的动作”或“让用户发现动作的线索”，比把两者混在一起更精确。

`prefers-reduced-motion` 能反映用户希望减少非必要动效的设置。实际设计可以减少、替换或移除相关动画，同时保留理解状态所需的反馈。[MDN：prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)

## 6. 把主观感受翻译成可执行请求

| 你观察到的感受 | 更精确的可能问题 | 可以怎样说 |
| --- | --- | --- |
| 看起来很散 | 缺少共享对齐线，相关项的距离相同 | “统一标题与内容左边界；组内间距缩小，组间间距扩大。” |
| 太像模板站 | 所有区块都用同尺寸卡片和相同强调方式 | “根据材料列表、长文阅读和任务状态分别选择列表、阅读面与状态条。” |
| 很空但又乱 | 留白没有表达关系，装饰占用注意力 | “把空间分配给段落与任务分组，合并无独立语义的容器。” |
| 很拥挤 | 内容优先级、密度与可展开详情没有配合 | “保留当前任务必要字段，技术详情可展开，列表提供密度切换。” |
| 很廉价 | 字体层级、图标、边界和阴影缺乏一致规则 | “统一字重、图标笔画和圆角档位，压低装饰表面数量。” |
| 看着累 | 行宽、行高、对比度或持续动效造成负担 | “用真实长文调整阅读宽度和行高，关闭闲置动画，实测文字对比。” |
| 重点不明显 | 多个区域同时抢占强调色和大字号 | “只强调当前任务与主要动作，次要操作回归文字或描边。” |
| 太‘AI 味’ | 泛化口号、满屏渐变、等权卡片、无具体内容 | “用真实任务文案和数据结构重做信息层级，再选择少量品牌元素。” |

“AI 味”是对结果的主观感受，适合进一步拆解。渐变、圆角或卡片本身都可用于优秀设计；决定质量的是它们是否解释信息、支持操作并形成一致的视觉语言。

## 7. 一份完整的视觉方向提示词

```text
任务：为一个长时间使用的资料管理工具设计“材料阅读与证据核对”页面。

使用情境：用户在左侧挑选材料，在中心阅读原文，在右侧核对来源与分析结果。
艺术方向：工具型骨架 + 编辑式内容排版，温和中性色，单一深绿色强调。
信息层级：当前材料标题与主要操作第一层；原文第二层；来源、版本、时间第三层。
布局：桌面三栏；窄窗口将属性区收为可打开的面板；正文有最大阅读宽度。
排版：明确正文、辅助、分节标题、页标题四级；中英混排、长标题与代码各有规则。
表面：常驻区域以留白和细分隔线组织；菜单和弹窗使用更明确层高。
状态：展示加载、空材料、无检索结果、错误、选中、键盘焦点和长任务进行中。
交付：先给一份简短设计说明与 tokens；再实现一个代表性页面。
验收：提供浅色/深色、宽/窄窗口以及键盘操作证据；说明偏离规格的理由。

先读取现有设计与组件约定，复用已有能力。具体字段以真实项目数据为准。
```
